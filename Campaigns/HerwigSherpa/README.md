# Herwig VariableKKS vs Sherpa Variable Flavours

This campaign compares the Herwig 7.3 QCD-instanton implementation with
Sherpa 3.0.4. Herwig uses `VariableKKS`; Sherpa uses its native energy-threshold
flavour prescription. The comparison covers `gg` and all supported strong
initial states in the low- and high-mass setups.

The campaign configuration is in [`campaign.json`](campaign.json). Canonical
cards are generated by [`run_campaign.py`](run_campaign.py) and are committed
so that every physics setting remains inspectable.

## Physics Definition

| Setting | Value |
| --- | --- |
| Beam energy | `6500 GeV` per proton |
| PDF | `NNPDF31_nnlo_as_0118`, member 0, in every PDF slot |
| Scale | `mu^2 = shat/<N_g>` |
| Gluon distribution | KKS Poisson mean, modifier 1 |
| Literal final-parton cap | 29 |
| MPI | Off |
| Low mass | `30..2895.5 GeV` |
| High mass | `500..2895.5 GeV` |
| Events per low profile | 50,000 |
| Events per high profile | 20,000 |
| Shards | 10 per generator/profile |

Both generators use the requested outgoing zero-mode masses

```text
u = 0.0023, d = 0.005, s = 0.093, c = 1.27, b = 4.18 GeV.
```

Herwig uses MAMBO, `Random3`, `General` shower reconstruction,
`GluonCounting FinalState`, `NAdditional 25`, and `MaxFinalPartons 29`.
Sherpa uses its CSS shower, Ahadic fragmentation, and native random colour
assignment. These shower, hadronization, and individual colour-flow
probabilities are intentionally not forced to be identical.

For quark-initiated profiles, Herwig's incoming collinear PDF legs remain
massless even though MAMBO gives the outgoing legs their nominal masses.
Sherpa's instanton code has one global particle-mass setting and also passes
those masses to incoming RAMBO kinematics. There is no separate stock Sherpa
switch for incoming and outgoing masses, so this `All`-only convention
difference is retained and documented instead of making the outgoing bottom
quarks massless.

Sherpa initializes its MPI PDF objects even when `MI_HANDLER: None`. The cards
therefore assign the same PDF and member to both the hard-process and inactive
MPI slots. This avoids a hidden fallback to a different set without enabling
MPI.

## Flavour Prescriptions

Herwig partitions the inclusive KKS cross section between four- and
five-flavour channels using the `VariableKKS` fermion factors. The result is a
scale-dependent probability involving `rho`, the fermion overlap, and
`KKSBottomMass = 4.18 GeV`.

Sherpa uses

```yaml
INSTANTON_INCLUDE_QUARKS: 5
INSTANTON_C_PRODUCTION_THRESHOLD: 20.0
INSTANTON_B_PRODUCTION_THRESHOLD: 100.0
```

Charm is active throughout this campaign. Sherpa switches bottom production
on sharply at an instanton mass of 100 GeV, whereas Herwig has no equivalent
fixed energy threshold. This difference is the main model comparison, not a
parameter mismatch.

Stock Sherpa applies these thresholds while constructing the outgoing
zero-mode state, but not to a crossed incoming flavour. In an `All` sample,
a subprocess with exactly one incoming bottom below 100 GeV can consequently
produce unequal colour and anticolour counts and abort in the shower. The
campaign-local patch applies the same flavour threshold to incoming legs:
bottom-initiated subprocesses contribute only above 100 GeV, and an additional
colour-balance guard rejects malformed states before showering.

## Cross-Section Convention

Sherpa 3.0.4 multiplies the tabulated partonic cross section by an internal
`1/36`. The primary cards set

```yaml
INSTANTON_SIGMAHAT_MODIFIER: 36.0
```

so both generators use the same tabulated inclusive normalization. A Sherpa
modifier of 1 would instead restore Sherpa's native one-thirty-sixth
normalization. This global factor does not change generated shapes.

## Process Sets

The `gg` cards contain only `g g`.

The Sherpa `All` cards list 56 unordered incoming channels explicitly:
one `gg`, ten `qg` or antiquark-gluon, twenty distinct-flavour same-sign
quark channels, and twenty-five quark-antiquark channels. Equal-flavour
same-sign `qq` and antiquark-antiquark states are excluded because a
one-instanton zero-mode set cannot supply two crossed legs of the same sign
and flavour.

Herwig `Processes All` registers the corresponding families for both its
four- and five-flavour branches.

## Setup

Activate the Herwig installation that supplies Herwig 7.3, Rivet, LHAPDF,
HepMC3, GSL, and CMake:

```sh
source /path/to/Herwig/bin/activate
```

The driver uses `SHERPA_SOURCE` when set. Otherwise it looks for the local
Sherpa 3.0.4 source at
`~/Projects/Pull/summer2026_new/Sherpa/sherpa-v3.0.4`.

Check the environment and regenerate cards:

```sh
python3 Campaigns/HerwigSherpa/run_campaign.py render --check
python3 Campaigns/HerwigSherpa/run_campaign.py doctor
```

Build the Herwig matrix-element plugin, Rivet analysis, and a campaign-local
Sherpa 3.0.4 with Rivet and HepMC3 enabled:

```sh
python3 Campaigns/HerwigSherpa/run_campaign.py build --component all
```

Build products are kept under `.build/` and `.local/` and are not committed.
Runs require this patched campaign-local Sherpa by default. `SHERPA_BIN` may
override it only when deliberately pointing to an equivalently patched build.
The installed Rivet 4.1.2 is linked against HepMC3 3.2.5, while Sherpa 3.0.4's
CMake finder requests 3.2.6 for Rivet 4. The build command therefore creates
an ignored Sherpa source mirror and applies four tracked patches:

- [`sherpa-rivet-hepmc325.patch`](patches/sherpa-rivet-hepmc325.patch) accepts
  the installed HepMC3 3.2.5 for this Rivet build.
- [`sherpa-rambo-incoming-masses.patch`](patches/sherpa-rambo-incoming-masses.patch)
  fixes the generic Sherpa 3.0.4 RAMBO incoming-mass calculation, whose stored
  squared masses were squared a second time. Without it, a low-mass
  bottom-initiated channel could receive an unphysical threshold near
  `2 m_b^2`.
- [`sherpa-instanton-upper-bound.patch`](patches/sherpa-instanton-upper-bound.patch)
  handles the final instanton table node directly; the unpatched interpolator
  dereferences its past-the-end iterator at exactly `2895.5 GeV`.
- [`sherpa-instanton-incoming-thresholds.patch`](patches/sherpa-instanton-incoming-thresholds.patch)
  applies Sherpa's charm and bottom activation thresholds consistently to
  crossed incoming flavours and checks colour balance before constructing a
  flow. This is required for `All` samples that extend below a heavy-flavour
  threshold.

The RAMBO patch is not instanton-specific. It is required to run the matched
massive `All` comparison and is kept visible rather than silently altering the
user's Sherpa checkout.

## Validation And Production

Run all eight 20-event smoke samples:

```sh
python3 Campaigns/HerwigSherpa/run_campaign.py smoke
python3 Campaigns/HerwigSherpa/run_campaign.py validate --smoke
python3 Campaigns/HerwigSherpa/run_campaign.py summarize --smoke
```

The smoke cards retain every configured process but use one 500-point Herwig
integration iteration. Production cards retain the two 10,000-point
iterations in `cards/herwig/common.in`. Smoke cross sections are consequently
only structural checks, not precision comparisons.

Run the complete 280,000-event campaign:

```sh
python3 Campaigns/HerwigSherpa/run_campaign.py run
```

Individual work can be selected, for example:

```sh
python3 Campaigns/HerwigSherpa/run_campaign.py run \
  --generator sherpa --profile all-low --shards 0,1
```

Every shard receives a stable, profile-derived seed and a `provenance.json`
containing its exact command, event count, card hash, source commit, and plugin
and generator-executable hashes. Herwig's content-addressed production
integration is performed once per profile and reused by all of that profile's
shards. Concurrent campaign commands lock only this one-time preparation;
event generation remains independent.

Merge and validate the complete results:

```sh
python3 Campaigns/HerwigSherpa/run_campaign.py merge
python3 Campaigns/HerwigSherpa/run_campaign.py validate --results
python3 Campaigns/HerwigSherpa/run_campaign.py summarize
```

The existing `QCD_INSTANTON_KKS` analysis normalizes finite histograms to unit
area. Its counters remain accepted-event efficiencies. Absolute cross sections
are extracted from the Herwig integration summary and the sum of Sherpa's
subprocess summaries by the `summarize` command; they are not reconstructed
from normalized Rivet histograms.

## Plots

Create Herwig/Sherpa overlays and ratio panels:

```sh
python3 Campaigns/HerwigSherpa/run_campaign.py plot
```

PDF and PNG are rendered in separate passes. This avoids the local plotting
stack interpreting `pdf,png` as one unsupported Matplotlib format.
The driver also supplies a writable Matplotlib cache and ignores a missing
TeX-tree override from the active generator environment.

Generated runs, logs, YODA files, result databases, and plots live under
ignored campaign directories. Only configuration, source, cards, tests, and
documentation belong in Git.
